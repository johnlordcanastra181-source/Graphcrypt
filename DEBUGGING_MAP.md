## 2. Frontend wiring

**Script load order** (`templates/index.html:1342-1347`) — matters, because `app.js` instantiates classes defined in the earlier files:

```
i18n_explanations.js  → window.I18N_LANGUAGES / I18N_UI / I18N_EXPLANATIONS
                         window.formatI18nText / getCurrentLanguage / setLanguage
graph_editor.js       → class GraphEditor
astar_ui.js           → class AStarUIController
crypto_ui.js          → class CryptoUIController
text_suite_ui.js      → class TextSuiteController
app.js                → DOMContentLoaded: creates all 4, wires nav + toolbar
```

**Boot order inside `app.js` (DOMContentLoaded):**
1. `new GraphEditor('graph-svg','graph-canvas-container')`
2. `new AStarUIController(editor)`, `new CryptoUIController()`
3. `new TextSuiteController()` — separate `DOMContentLoaded` listener in `text_suite_ui.js:1507`
4. `await loadGraphFromAPI()` → `GET /api/graph` → `editor.loadGraph()` → triggers `onGraphChanged`
5. `astarUI.runFullAStar()` — runs A* A→T on load

**Critical:** `app.js` binds its elements through a safe `on(id, event, handler)` helper. A missing element id logs a console warning and is skipped, instead of throwing a `TypeError` that used to kill the whole init block (including step 4/5) and leave the page silently blank. If the UI is blank, check the browser console *first*.

**Refresh fan-out:** `editor.onGraphChanged` → `astarUI.updateNodeDropdowns()` + `cryptoUI.syncPathFromServer()`. Any graph mutation triggers 2 API calls (`GET /api/astar/last`, then the cipher/export fetches that the sync issues).

## 3. Data flow per feature

### Graph editor
`GraphEditor` (browser) → REST → `Graph` (server, authoritative) → response → `editor.loadGraph()` → full SVG re-render.
The browser keeps a **shadow copy** in `this.nodes` / `this.edges` Maps. It is only reconciled by re-fetching `/api/graph`. Mutations (add/delete/drag) call the API then update the local Map optimistically.

### A* pathfinding
`POST /api/astar/run` → `astar.run_astar(graph_instance, start, goal, heuristic)`
→ returns `{success, path, path_edges, total_cost, visited_nodes, evaluated_edges, steps[], execution_time_ms}`
→ `astar_ui.playSearchAnimation(data)` replays `steps[]` on a `setInterval` (30–180 ms/step, scaled by step count) calling `editor.setPathHighlights()` each tick.
Final tick calls `cryptoUI.onAStarCompleted(data)` → syncs the crypto panel to the new path.

`steps[]` is the debugging artifact: each entry has `current_node`, `action` (human string), `open_set`, `closed_set`, `g_scores`, `f_scores`, `highlight_edge`.

### Cipher / export
`GET /api/astar/last` → returns the cached `last_astar_result` (path, path_edges,
total_cost, heuristic). This is how the Encryption panel stays in sync with the
server instead of holding a hardcoded sample path.

`POST /api/cipher/encrypt` → `cipher.get_edge_transformations(graph, path_nodes, shift)`
→ per-edge mod-10 digit shift: `encrypted_digit = (digit + shift) % 10` applied to **each digit of the number string**, e.g. `363.8` with shift +3 → `696.1`.
Note: the cipher shifts the *digits of the weight*, not the weight value. `12 → 45`, `106.9 → 439.2`.

`POST /api/export/preview` → `exporter.generate_concise_txt` (all edges + metadata) or `generate_full_report_txt` (full analytical report).

## 4. Where to look when something breaks

| Symptom | Start at | Notes |
|---|---|---|
| Blank page / nothing happens | Browser console → `app.js` | Bindings go through the `on()` helper; a missing id logs a warning instead of killing init |
| Wrong shortest path | `astar.py` `run_astar` | Check `steps[]` g/f scores; heuristic admissibility |
| Path cost doesn't match path | `astar.py` `total_cost = g_score[goal_id]` | Not the sum of edge weights — it's the g-score |
| Encryption numbers look wrong | `cipher.py:encrypt_weight_value` | Per-digit shift; `5.0` → `"5"` → `8` |
| Export text wrong | `exporter.py` | `generate_concise_txt` lists **all** edges, not just path |
| Pattern tiles show `0` / `-` | `text_suite_ui.js` `renderPatternResults` | Tiles are `stat-pattern-matches` / `stat-pattern-indices` |
| Modal dropdowns unusable | `graph_editor.js` `promptAddEdge` | Must reset `selSource.disabled` / `selTarget.disabled` to false |
| Numbers change between runs | `algorithms/optimization.py` | The GA uses a local `random.Random(42)`; never seed the global RNG |
| A* result stale in export | `app.py` `last_astar_result` | Module global, survives across requests; read it via `GET /api/astar/last` |
| 400 error on any POST | `app.py` `_int_field` / `_float_field` | Numeric fields are validated centrally and return 400 with the offending field name |

fixed on 2026-10-22. To confirm a test still catches its bug, stash the source

## 6. Confirmed bugs — ALL FIXED 2026-10-22

Each entry below records the original defect, the fix that landed, and where the
regression test lives. Regression tests: `tests/test_bugfix_regressions.py`.


### Bug 1 — Empty POST body creates a node named `"None"` (201) — FIXED
`app.py:77` → `node_id = data.get("id") or data.get("name")` → both `None` → `str(None).strip()` = `"None"` → a real node is created.

```
POST /api/nodes  {}        → 201  {"node": {"id": "None", "name": "None", ...}}
```
**Fix landed:** `add_node` now rejects a missing/blank `id` with 400 before calling
`graph_instance.add_node`, and validates `x`/`y` as numbers.
`POST /api/nodes {}` → **400** `{"error": "Node id or name is required."}`.
*Tests:* `TestBug1EmptyNodePayload`.

### Bug 2 — 500 instead of 400 on bad numeric input — FIXED
`int(data.get(...))` with no `try/except` in 8 places. The global handler (`app.py:49-54`) turns the `ValueError` into a 500 JSON.

| Route | Payload | Before | After |
|---|---|---|---|
| `POST /api/export/download` | `{"shift":"abc"}` | 500 | **400** |
| `POST /api/search/pattern` | `{"max_distance":"abc"}` | 500 | **400** |
| `POST /api/optimization/run` | `{"capacity":"abc"}` | 500 | **400** |
| `POST /api/optimization/run` | `{"population_size"/"generations"/"crossover_rate":"abc"}` | 500 | **400** |
| `POST /api/parallel/search` | `{"workers":"abc"}` | 500 | **400** |
| `POST /api/randomized/quickselect` | `{"k":"abc"}` | 500 | **400** |
| `POST /api/randomized/monte-carlo` | `{"sample_size":"abc"}` | 500 | **400** |
| `POST /api/nodes` | `{"id":"Q1","x":"abc"}` | 500 | **400** |

**Fix landed:** added `_int_field()` / `_float_field()` helpers in `app.py` that raise
`ValueError` on bad input; every numeric route now catches it and returns 400 with a
message naming the offending field. `_json_body()` also replaced the bare
`request.get_json() or {}` calls so malformed payloads no longer raise.
*Tests:* `TestBug2BadNumericInputReturns400` (13 cases).

### Bug 3 — QuickSelect out-of-bounds returns `success: true` — FIXED
`algorithms/parallel_random.py:224-225` returns `{"error": "Index k out of bounds", "element": None}`, and `app.py:513-514` spread it into `{"success": True, **result}`. The JS `text_suite_ui.js` checked `if (data.success)` → rendered `Rank k=99 Element: "null"`.

```
POST /api/randomized/quickselect {"items":[1,2,3],"k":99}
  before → 200 {"element": null, "error": "...", "success": true}
  after  → 400 {"success": false, "element": null, "error": "Index k out of bounds"}
```
**Fix landed:** the route returns 400 when the result carries an `error` key, and
`text_suite_ui.js` now checks `!res.ok || !data.success` and surfaces the message
as a toast instead of rendering `null`.
*Tests:* `TestBug3QuickSelectOutOfBounds`.

### Bug 4 — Pattern-match stat tiles never update (dead code) — FIXED
`text_suite_ui.js` read `document.getElementById('pattern-results-summary')` — **that id does not exist in `index.html`**. The update block was guarded by `if (summaryBox)`, so it never ran.

The stat tiles `stat-pattern-matches` (`index.html:733`) and `stat-pattern-indices` (`index.html:737`) exist but stayed at their initial `0` / `-`.

**Fix landed:** the block now binds `stat-pattern-matches` / `stat-pattern-indices`
directly and guards each tile individually. Verified live: a 3-match search now
shows `3` and `0, 15, 22` instead of `0` / `-`.
*Tests:* `TestBug4PatternStatTiles`.

### Bug 5 — Add-Edge modal dropdowns permanently disabled — FIXED
`graph_editor.js` (`promptEditEdgeWeight`) sets `selSource.disabled = true; selTarget.disabled = true;`. `promptAddEdge` never reset them, so every later **Add Edge** modal had frozen source/target selects.

**Fix landed:** `promptAddEdge` now sets `selSource.disabled = false; selTarget.disabled = false;`
before populating the options. Verified live: edit an edge → open Add Edge →
both selects are enabled and hold 20 options.
*Tests:* `TestBug5EdgeModalDropdownsStaysEnabled`.

### Bug 6 — "Graph Editor" nav tab shows the same view as "A* Pathfinding" — FIXED
`app.js` — `tab-editor` and `tab-astar` both did `viewAstar.classList.add('active-view')`. There is no `view-editor` section in `index.html`; the only difference between the two nav buttons was the workflow breadcrumb step (1 vs 2).

**Fix landed:** the editor tab now toggles an `editor-focus-mode` class on
`#view-astar`. `style.css` hides `.astar-control-panel` and drops the canvas
border in that mode, so the Graph Editor tab is a genuinely different screen
(full-width canvas) instead of a duplicate of the A* tab.
*Tests:* `TestBug6EditorAndAStarTabsDiffer`.

### Bug 7 — Stale hardcoded path in the crypto panel — FIXED
`crypto_ui.js` initialised `currentPathNodes = ['A','C','F','J','P','R','S','T']` and `currentTotalWeight = 1382.6` — the sample graph's A→T answer. After any graph edit the Encryption tab showed that stale path and cost.

**Fix landed:** the hardcoded values are gone. The crypto controller starts empty and
pulls the authoritative result from a new `GET /api/astar/last` endpoint
(`syncPathFromServer()`), which `app.js` calls on load and on every graph change.
`index.html`'s placeholder path pills were replaced with a neutral "Run A* …" hint.
Verified live: setting edge `e_A_C` to 5000 and re-running A* moved the panel to
`A → B → D → G → I → M → N → T` (1475.7) instead of the frozen sample path.
*Tests:* `TestBug7CryptoPanelHasNoStaleHardcodedPath`.

### Bug 8 — A* API default destination doesn't match the UI — FIXED
`app.py` defaulted `goal_node` to `"E"`; the JS default and the sample graph's farthest node are `"T"` (`astar_ui.js:80`, `graph.py:102`). A `POST /api/astar/run {}` with no body targeted the wrong node.

**Fix landed:** the default is now `"T"`, matching the UI and the sample graph.
*Tests:* `TestBug8AStarDefaultGoal`.

### Bug 9 — Debug server bound to all interfaces — FIXED
`app.py` and `run.py` called `app.run(host="0.0.0.0", port=..., debug=True)`. Flask's dev server is threaded by default, and `debug=True` exposes the Werkzeug interactive debugger (which has a Python console) to every interface on the LAN.

**Fix landed:** the server binds to `127.0.0.1` and `debug` is off by default.
Both are opt-in via environment variables:
`GRAPHCrypt_HOST=0.0.0.0` to expose on the LAN, `GRAPHCrypt_DEBUG=1` for the debugger.
`GRAPHCrypt_SECRET_KEY` also replaces the hardcoded `SECRET_KEY` (a random
per-process key is generated when it is unset).
*Tests:* `TestBug9ServerNotExposedToLan`.

### Bug 10 — `random.seed(42)` in the GA resets global RNG state — FIXED
`algorithms/optimization.py` seeded the **global** `random` module, so Monte Carlo sampling and Randomized QuickSort/QuickSelect produced different results depending on whether a GA run happened first in the same process.

**Fix landed:** the GA now uses a dedicated `rng = random.Random(42)` instance and
never touches the global module. Verified: the global RNG stream, QuickSort output,
and Monte Carlo frequencies are identical with and without an intervening GA run.
*Tests:* `TestBug10GlobalRngNotClobbered`.

## 7. Design / performance notes

### Fixed on 2026-10-22
- **`Graph.get_neighbors` was O(E)** — a linear scan over all edges, called once per A* expansion. Now backed by a `Graph._adjacency` index (node id → edge ids), so it is O(degree). The index is maintained by `add_edge` / `delete_edge` / `delete_node` / `clear`.
- **`evaluated_edges_order` was a list with `in` checks** → O(E²) over a run. A parallel `evaluated_edges_seen` set now makes the membership test O(1).
- **`GraphEditor.render()` rebuilt the entire SVG on every `mousemove`** while dragging. Drag now calls `scheduleRender()`, which coalesces to one render per animation frame.
- **`exporter.generate_concise_txt` docstring lied** — it showed only path edges while the code emits every edge. The docstring now says so.
- **LZW round-trip verification duplicated the encoder.** The inline re-implementation in `algorithms/compression.py` is replaced by a shared `_lzw_encode()` helper used by both `lzw_compress` and the verifier, so they cannot drift.
- **Hardcoded `SECRET_KEY`** — now read from `GRAPHCrypt_SECRET_KEY`, falling back to a random per-process key.
- **No favicon** — `GET /favicon.ico` now returns an inline SVG (200).
- **`knapsack_*` used `items.index(it)`** — dict equality, so duplicate items resolved to the first index. Both the DP and the greedy solver now track the true original index.
- **Blank-page risk** — `app.js` chained ~25 unguarded `document.getElementById(...).addEventListener(...)` calls; one missing id killed the whole init block. All 17 bindings now go through a safe `on(id, event, handler)` helper that logs a warning and continues.

### Still open
- **Unsynchronised global state.** `graph_instance`, `last_astar_result`, `last_shift_value` are module-level globals. The dev server is threaded → concurrent requests can interleave graph mutations and A* results. Single-user use is fine; anything concurrent is not. A `threading.Lock` around the mutating routes would close this.
- **Approximate search cost** is `O(n · m · k)`; a large `max_distance` on a long corpus is a hang risk.
- **`app.js` still refreshes the crypto panel on every graph change**, which costs one extra `GET /api/astar/last` round trip per mutation.

## 8. Conventions worth knowing

- **Explanations are in Filipino/Tagalog.** `flow_explanation` and `why_result` in every `algorithms/*` result are Tagalog strings, plus the parallel English i18n layer in `i18n_explanations.js`. Backend text is never English-only.
- **`app.py` returns two shapes.** Most routes return `{success: true, ...}`; `/api/search/pattern` returns `{success, mode: "comparison"|"single", ...}` where the single-algorithm payload is nested under `result`. `text_suite_ui.js` branches on `data.mode`.
- **Telemetry keys are consistent.** Every algorithm result carries `comparisons`, `time_microseconds`, `flow_explanation`, `why_result`, plus method-specific extras (`lps_table`, `bad_char_table`, `sample_dictionary_entries`, `convergence_history`, …).
- **The complexity matrix is static data** — `algorithms/complexity_data.py` is a hardcoded list of 14 records, not computed. `GET /api/complexity/matrix` just returns it.
